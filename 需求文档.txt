## 1. 项目概述

### 1.1 项目背景

2025 年中国新能源汽车市场在售车型已超过 400 款，消费者面临严重的信息过载问题。传统汽车垂直网站（懂车帝、汽车之家）虽然数据丰富，但存在以下痛点：

- **信息碎片化**：参数、口碑、销量分散在不同页面，用户需手动切换对比
- **缺乏个性化**：无法根据用户家庭情况、通勤需求、预算约束给出智能推荐
- **决策成本高**：用户需自行理解复杂参数（CLTC 续航 vs 实际续航、磷酸铁锂 vs 三元锂）
- **时效性差**：静态页面无法反映最新销量、降价、口碑变化

大语言模型（LLM）与 Agent 技术的成熟为解决上述问题提供了新思路。本项目旨在构建一个具备**自主规划、工具调用、知识检索、多轮记忆**能力的智能导购 Agent，并以零成本方式完成工程化部署。

### 1.2 项目目标

| 目标类型 | 具体描述 | 量化指标 |
|---------|---------|---------|
| 核心功能 | 基于多轮对话理解用户需求并推荐车型 | 意图识别准确率 ≥ 85% |
| 知识检索 | 基于本地知识库准确回答参数查询 | RAG 回答准确率 ≥ 90% |
| 联网能力 | 获取最新销量、口碑、新闻信息 | 联网成功率 ≥ 80% |
| 对比分析 | 自动生成多车型对比报告 | 对比维度覆盖率 ≥ 6 项 |
| 工程化 | Docker 一键部署 + 在线可访问 | 部署时间 ≤ 5 分钟 |
| 成本控制 | 全流程零成本 | API 费用 ≈ 0 元 |

### 1.3 项目范围

**包含内容**：
- 新能源汽车基础参数知识库（覆盖 50+ 热门车型）
- 多轮对话式选车 Agent（LangChain ReAct 模式）
- 联网搜索增强工具（DuckDuckGo）
- 竞品对比报告生成
- Gradio Web 交互界面
- Docker 容器化 + GitHub 代码托管 + Hugging Face Spaces 在线演示

**不包含内容**（明确边界，避免范围蔓延）：
- 真实交易/下单功能
- 用户账号体系
- 车机数据接入
- 图片/视频内容生成
- 移动端适配
- 高并发支持

### 3.2 功能模块详细说明

#### 模块一：对话交互与意图识别（P0）

| 项目 | 内容 |
|------|------|
| 功能描述 | 接收用户自然语言输入，识别用户意图类型 |
| 意图类型 | `recommend`（推荐）、`query_params`（参数查询）、`compare`（对比）、`market_info`（市场信息）、`calculate`（计算）、`chat`（闲聊） |
| 输入 | 用户自然语言文本 |
| 输出 | 结构化的意图标签 + 提取的实体（预算、车型、需求关键词） |
| 实现方案 | 使用 Qwen LLM 的 Function Calling 能力，定义 `classify_intent` 函数 |

**验收标准**：
- 正确识别 6 种意图类型
- 实体提取准确率 ≥ 85%
- 单次意图识别延迟 ≤ 2 秒

#### 模块二：基于 RAG 的车型参数知识库（P0）

| 项目 | 内容 |
|------|------|
| 功能描述 | 构建新能源汽车参数知识库，支持语义检索 |
| 数据来源 | 手工整理的 CSV/JSON 文件（覆盖 50+ 热门车型） |
| 数据字段 | 品牌、车型、价格区间、续航里程(CLTC)、电池类型、电池容量、轴距、车身尺寸、驱动方式、百公里加速、智驾等级、安全配置 |
| 向量化 | 使用 Qwen Embedding API（text-embedding-v3） |
| 存储方案 | ChromaDB 本地持久化存储（Docker Volume 挂载） |

**验收标准**：
- 知识库车型数量 ≥ 50 款
- 参数查询准确率 ≥ 90%
- RAG 检索延迟 ≤ 1.5 秒

#### 模块三：联网搜索增强（P1）

| 项目 | 内容 |
|------|------|
| 功能描述 | 当本地知识库无法回答时，自动触发联网搜索 |
| 搜索范围 | 销量数据、车主口碑、最新新闻、价格变动 |
| 实现方案 | DuckDuckGo Search（免费、无需 API Key） |
| 结果处理 | 搜索结果经 LLM 摘要后再返回给用户 |
| 超时策略 | 设置 3 秒超时，失败时降级为本地数据回答 |

**验收标准**：
- 联网搜索成功率 ≥ 80%
- 搜索结果相关性 ≥ 70%
- 搜索摘要长度控制在 100 字以内

#### 模块四：竞品对比分析（P1）

| 项目 | 内容 |
|------|------|
| 功能描述 | 对两款或多款车型进行多维度对比 |
| 对比维度 | 价格、续航、动力性能、空间尺寸、智驾能力、安全配置、用车成本 |
| 输出格式 | Markdown 表格 + 文字总结 + 购买建议 |
| 实现方案 | 先查本地库获取基础参数 → 联网获取市场表现 → LLM 生成结构化对比报告 |

**验收标准**：
- 对比维度覆盖 ≥ 6 项
- 对比报告生成时间 ≤ 10 秒
- 输出包含客观参数和主观建议两部分

#### 模块五：多轮对话记忆（P0）

| 项目 | 内容 |
|------|------|
| 功能描述 | 记住对话上下文中的关键信息 |
| 记忆内容 | 用户预算、家庭情况、偏好品牌、已讨论过的车型 |
| 实现方案 | LangChain ConversationBufferMemory + 自定义实体提取器 |
| 典型场景 | 用户说"第二个的续航呢？"时能正确指代之前推荐的车型 |

**验收标准**：
- 5 轮对话内上下文保持准确率 ≥ 90%
- 指代消解准确率 ≥ 80%

#### 模块六：落地价格计算（P2）

| 项目 | 内容 |
|------|------|
| 功能描述 | 根据裸车价格计算落地价 |
| 计算项 | 购置税（新能源减免）、保险、上牌费、贷款方案 |
| 实现方案 | Calculator Tool（Python 函数，通过 Function Calling 调用） |

**验收标准**：
- 计算结果准确（与官方计算器误差 ≤ 1%）
- 支持全款和贷款两种方案

### 5.3 核心流程设计

#### 5.3.1 Agent 决策流程（ReAct 模式）

```
用户输入
    │
    ▼
[意图识别] ──→ 提取实体（预算、车型、需求）
    │
    ▼
[规划器] ──→ 决定执行路径：
    │          ├─ 参数查询 → RAG Tool
    │          ├─ 车型推荐 → RAG + 计算推理
    │          ├─ 竞品对比 → RAG + Search Tool
    │          └─ 市场信息 → Search Tool
    │
    ▼
[执行器] ──→ 循环执行：Thought → Action → Observation
    │
    ▼
[答案生成] ──→ 基于工具返回结果 + 用户上下文
    │
    ▼
[输出渲染] ──→ Markdown 格式（表格、列表、总结）
```

#### 5.3.2 System Prompt 设计要点

```yaml
role: 资深新能源汽车销售顾问
constraints:
  - 仅基于工具返回的数据回答，禁止编造
  - 数据不足时必须说明，不得猜测
  - 推荐时需说明理由
  - 避免使用过于专业的术语，除非用户主动询问
output_format:
  - 推荐结果：先总结，再分条列出
  - 对比结果：使用 Markdown 表格
  - 参数查询：直接给出准确数据 + 数据来源
```

## 6. 数据需求

### 6.1 数据来源

| 数据源 | 获取方式 | 更新频率 | 用途 |
|-------|---------|---------|------|
| 懂车帝/汽车之家 | 手工整理 CSV | 项目初始化时一次性采集 | 静态参数知识库 |
| DuckDuckGo | 实时搜索 API | 每次查询时实时获取 | 销量、口碑、新闻 |

### 6.2 知识库数据字段定义

```csv
brand,model,price_min,price_max,range_cltc,battery_type,battery_capacity,axis_length,length,width,height,drive_type,acceleration,ad_level,safety_features,selling_points
```

## 9. 风险与应对

| 风险 | 影响 | 概率 | 应对策略 |
